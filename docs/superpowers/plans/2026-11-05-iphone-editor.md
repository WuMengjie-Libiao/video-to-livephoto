# iPhone 视频转实况与手机布局

目标：iPhone 本地选视频 → 时间线截取 → 选封面 → 系统实况预览 → 确认保存；随后补齐现有 React 小屏界面。用户确认先完成 iPhone 流程。

证据：现有 ios-import 只有两个文件导入表单，Electron 不能直接运行在 iPhone。iOS 16 起可用 PhotosPicker/FileRepresentation，AVFoundation 完成本地剪辑，PhotosUI 播放实际 Live Photo。保留已有 iOS 16 部署目标，不新增第三方媒体库。

设计与取舍：
- 不将 Electron 放进网页壳；以现有 SwiftUI 目标实现原生相册选择、安全区、44pt 触控、动态字体和深色模式。
- 把已验证的 JPEG 标识/MOV 时间轨/PhotoKit 配对层从 macOS CLI 分出到共享 Swift 文件，桌面与 iOS 共用；原 CLI 接口保持不变。
- iOS AVFoundation 将选段和可选音轨导出为本地标准视频，再提取实际封面、封装配对；预览对象持有不可变文件，确认保存同一份，不再次编码。预览前不申请写入权限、不写相册。
- 来源文件复制到本应用临时目录，文件选择权限仅覆盖复制过程；每次替换、丢弃预览和失败均清理对应临时目录。生成与保存期间禁止改变来源或重复保存。
- 时间线使用可访问的原生横向手势，允许纵向滚动；选段/封面约束由 ClipSelection 统一维护。

执行：
1. 分出共享配对层；增加选段模型与领域测试；迁移 mac 构建及 iOS/CI 来源。
2. 实现 iOS 导入、剪辑、成片生成、实况预览与保存，替换旧成对文件表单。
3. 构建到 iOS 模拟器，用合成视频验证选段、音轨、方向、实际配对识别、预览/返回/保存边界，检查大小屏、深色、大字体。仅在隔离模拟器相册执行写入测试。
4. 补齐 React 手机视口、安全区、触控和预览布局，用真实渲染/模拟触控验证，同时回归桌面剪辑。

验证限制：模拟器不能代替真实 iPhone 的编码性能、相册长按体验、iCloud 同步；签名安装到用户设备需要用户的开发签名，不擅自配置账号。

## 已完成与验证（2026-11-05）

- 共享层已拆出 JPEG/MOV 配对、PHLivePhoto 加载和 PhotoKit 保存，Mac CLI 命令不变；mac native 重新编译无警告。
- 原 iOS 配对表单已替换为视频导入、时间线、封面/声音、实际 PHLivePhotoView 预览、确认保存。临时资源由各自对象持有，关闭预览释放；移除了会在旧 sheet 关闭时清除新预览的多余 onDismiss。
- iPhone 16 与 SE 3（iOS 18.6）模拟器验证原生导入/缩略图、范围/封面、旋转、静音/保留音轨、实际实况识别、预览权限边界、返回调整和确认写入。SE 完整脚本返回 IPHONE_OK；原生正式入口通过界面操作完成系统相册选视频 → 预览 → 确认保存，观察到成功提示。
- 手机深色、大字体和 SE 小屏截图已查看；原生模拟器 UI 工具未能合成有效的连续拖动（普通 ScrollView 也未响应拖动），因此不声称原生拖柄的运行手势已验证。真正手指交互、性能、iCloud/聊天分享仍需真机验证。
- React 增加 viewport、安全区/动态视口、紧凑底栏、全屏成片预览和触控范围，修正纵向滚动会抢先更改播放位置的手势归属。Chromium 合成触控已验证横向拖柄、跨时间线纵向滚动不改播放位置；320×568、393×852、740×360、768×1024 不横向溢出，预览和确认按钮可访问；原桌面剪辑/保存回归通过。
- core 4 项通过；原生 helper 改动后已重新运行；最新 Mac 包的 FFmpeg/原生 helper、成片预览和保存验证通过 PACKAGED_OK。
- Xcode 当前缺少 26.5 平台组件导致目标枚举失败，未运行 XCTest 套件。独立选段领域检查通过；用 Apple SDK 直接编译并运行模拟器集成检查，arm64 真机二进制也已编译（min iOS16），生成未签名 IPA。安装真实手机需用户自己的签名。
